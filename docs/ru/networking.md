# Сетевой доступ и порты

Исходящими подключениями управляют daemon и policy gateway. По умолчанию активен профиль `deny-all`: агент не сможет подключиться к сети, пока правило не разрешит трафик.

## Разрешите исходящий трафик

Правила при создании принимают IPv4 CIDR и необязательный порт. По умолчанию используется TCP; для UDP добавьте префикс `udp:`:

```sh
rsbx run --allow-network 203.0.113.8/32:443 shell .
rsbx run --allow-network udp:203.0.113.53/32:53 shell .
```

В примерах используются специальные адреса для документации. Замените их только на адреса, нужные задаче. Запрет имеет приоритет над разрешением. Глобальные правила и правила sandbox показывает `rsbx policy ls`.

Доменные правила требуют настроенный DNS upstream и совместимую patched-сборку gateway. Проверка TLS для доменных правил остаётся экспериментальной. Для неё известны ограничения с encrypted ClientHello, UDP только по домену и пересечениями с прямыми IP-правилами. Не используйте доменное разрешение как универсальный DNS- или HTTP-фильтр.

## Опубликуйте порт

Опубликованные guest-порты привязываются к loopback host-системы и недоступны другим устройствам локальной сети:

```sh
rsbx run --publish 127.0.0.1:8080:3000 shell .
rsbx ports my-sandbox
```

Поддерживаются TCP и UDP. Формы IPv4 и IPv6 loopback доступны на совместимых сборках gateway. Guest-приложение должно слушать адрес, доступный из интерфейса sandbox, обычно `0.0.0.0`.

Публикация порта разрешает соединения с host в гостевую систему. Она сама по себе не разрешает гостю исходящие подключения. Для этого настройте отдельные egress-правила.

## Просмотр и изменение правил

```sh
rsbx policy ls my-sandbox
rsbx policy allow network --sandbox my-sandbox 203.0.113.8/32:443
rsbx policy deny network --sandbox my-sandbox 203.0.113.8/32:443
```

Локальная команда `policy check` оценивает сохранённые правила. Она не спрашивает gateway и не доказывает, что сетевой пакет будет пропущен.

## Ограничения

Проверки gateway зависят от платформы и сборки. Полная проверка исходящего IPv6, обходов через QUIC/DoH, HTTP-фильтрации и независимый security review не завершены. Текущая область проверок описана в [руководстве по безопасности](security.md).
