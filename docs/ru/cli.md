# Справочник CLI

Каноничный пользовательский бинарник — `rsbx`. Большинство команд принимают `--socket PATH`; переменная `SANDBOXES_SOCKET` задаёт сокет по умолчанию для текущей shell-сессии.

## Создание и запуск

```sh
rsbx run shell .
rsbx run --detach --name api --cpus 2 --memory 2g shell .
rsbx create --name api shell . /путь/к/docs:ro
```

Грамматика CLI определяет `run` как создание или повторное использование песочницы, запуск и подключение оболочки. Runtime и daemon содержат exec/PTY реализацию, но полный agent lifecycle ещё не прошёл общую platform acceptance. Текущий каталог используется по умолчанию. `--detach` возвращает управление после запуска; `create` создаёт песочницу без подключения. README CLI называет реализованным только адаптер shell; остальные агенты отмечены как preview или unsupported.

## Просмотр и управление

```sh
rsbx ls
rsbx get api
rsbx start api
rsbx stop api
rsbx exec -it api /bin/sh
rsbx rm --force api
```

`ls` показывает список песочниц, `get` — подробности, `ports` — опубликованные порты. `start`, `stop` и `rm` принимают несколько имён. Перед удалением требуется подтверждение, если не указан `--force`. `rm --all` удаляет все песочницы — сначала проверьте список.

## Workspace и файлы

```sh
rsbx run shell . /путь/к/reference:ro
rsbx cp ./input.txt api:/tmp/input.txt
rsbx cp api:/tmp/output.txt ./output.txt
```

Суффикс `:ro` подключает workspace только для чтения. `cp` копирует обычные файлы и каталоги; путь внутри гостя должен быть абсолютным. Реализация отклоняет traversal и неподдерживаемые типы файлов. Символические ссылки по умолчанию запрещены, если явно не включено следование по ссылке.

Пути workspace относятся к host-системе. Подключайте только необходимые агенту каталоги. Если у workspace есть право записи, процессы гостя смогут менять эти файлы host-системы. Суффикс `:ro` запрещает запись через это подключение, но не скрывает файлы внутри образа гостя.

## Переменные среды и секреты

```sh
rsbx exec -e MODE=debug api env
rsbx secret set openai --sandbox api
rsbx secret ls
rsbx secret rm openai --sandbox api
```

Используйте `-e KEY=VALUE` для переменной одной сессии. Значения в аргументах команды могут быть видны в списке процессов host-системы; не передавайте так секреты. `rsbx env plan [PATH...]` создаёт статический preview без изменений. Без путей читает `sbxenv.yaml` из текущего каталога и сначала объединяет необязательные defaults из `~/.sbxenv.yaml`; явно переданные файлы или каталоги объединяются по порядку и пропускают user defaults. YAML-значения поддерживают `${{ env.projectDir }}` и `${{ env.fileDir }}`. Preview показывает объявленные порты, но не открывает их. `args` проверяются через `--env-arg` и `--env-args-file`; значения скрыты в preview. Совокупный объём аргументных данных ограничен 8 MiB, количество значений — 20 000. Значения самого `--env-arg` могут быть видны в списке процессов, поэтому чувствительные значения передавайте через файл аргументов. Ссылки `${{ env.args.NAME }}` подставляются в YAML-значения один раз; аргументы kit пока не реализованы. Флаг `--name NAME` задаёт имя sandbox для preview. `rsbx env create [PATH...]` создаёт локальную песочницу из поддерживаемого набора полей: agent, name, workspace mounts, ports, environment variables, CPU и memory. В терминале команда запрашивает подтверждение; для неинтерактивного запуска используйте `--force`, который подтверждает только этот запуск. `rsbx env run` создаёт отсутствующую песочницу или подключается к существующей с совпадающей конфигурацией; `--detach` запускает её без подключения. `rsbx env exec` выполняет команду в совпадающей существующей песочнице и запускает её, если она остановлена. `rsbx env rm` удаляет только песочницу с совпадающими именем, agent и workspace. Kits, credential bindings, host-команды и MCP-декларации не поддерживаются и отклоняются. Для env lifecycle есть command/unit-test coverage; полная межплатформенная совместимость с Docker и live runtime acceptance ещё не подтверждены. `rsbx run --env` задаёт переменные только для одного запуска/сессии и не заменяет workflow с environment-файлом. `rsbx secret` хранит provider values в системном хранилище credentials и не записывает их в SQLite или логи. Перед использованием прочитайте [модель безопасности](security.md). Вход в Docker account работает отдельно и описан в разделе [Docker и Rheic](docker.md).

После обновления настройки читаются из прежнего пути `~/.config/klorq/settings.toml`, если файла настроек Rheic ещё нет. Сохранённые credentials остаются доступными из прежнего пространства имён системного хранилища; при повторном сохранении credential записывается в новое пространство, а старая запись удаляется.

## Сеть и порты

```sh
rsbx run --publish 127.0.0.1:8080:3000 shell .
rsbx ports api
rsbx policy ls api
```

По умолчанию исходящий трафик запрещён. Явные правила поддерживают IPv4 CIDR и домены, если их поддерживает настроенный gateway. Публикация портов ограничена loopback-адресами; внешние host bindings отклоняются. Успешная настройка `--publish` не разрешает гостю исходящие подключения. Добавляйте только необходимые адреса назначения.

## Docker

CLI принимает `--docker` для опционального профиля Docker внутри guest. Профиль может запустить `dockerd`, но вложенные `docker run/load/build` и Compose пока блокируются ограничениями `unshare` в текущем runtime. Это не означает, что VM не запускается. `rsbx login` сохраняет авторизацию Docker account на host-системе, но не передаёт registry credentials в гостевую среду. Актуальный статус и история описаны в [руководстве Docker](docker.md).

## Точная справка

Используйте встроенную справку установленной версии:

```sh
rsbx --help
rsbx run --help
rsbx policy --help
```

CLI находится в стадии pre-alpha, поэтому флаги и поведение могут меняться между выпусками.
