# Docker и Rheic

Сейчас у Rheic есть две отдельные функции, связанные с Docker: вход в Docker account на host-системе и экспериментальная настройка для запуска Docker Engine внутри песочницы. Это разные функции. Вход в аккаунт сам по себе не запускает Docker daemon в гостевой системе.

## Текущий статус

**Опциональный профиль запускает Docker daemon внутри guest, но вложенные операции с workload пока заблокированы в текущем checkout.** `docker info` проходил на прежней выпущенной сборке. В текущем runtime команды `docker run`, `docker load`, `docker build` и Compose не проходят настройку вложенной нагрузки из-за запрета `unshare`. Это не означает, что VM не запускается. Прежний патч cgroup и capabilities удалили, потому что он выдавал workload широкие привилегии внутри guest и доступ на запись к файловой системе guest cgroup. Не рассчитывайте на запуск вложенных контейнеров, пока отдельная cgroup-изоляция и минимальный набор привилегий не пройдут проверку и тесты.

Для предыдущих выпущенных версий модулей зафиксированы live-проверки Docker Engine 29.9.2, команды `docker run --rm hello-world`, постоянного хранилища и stop/start. Эти результаты относятся к исторической сборке и её профилю; они не подтверждают работу текущего checkout и не закрывают security review.

## Вход в Docker account

CLI сохраняет авторизацию Docker account через локальный daemon. В текущем исходном коде также есть экспериментальный host broker для pull и push Docker Hub из guest. Он прошёл synthetic contract-тесты, но ещё не выпущен и не прошёл live-проверку VM или сравнение с той же версией `sbx`. Не считайте его production-ready или parity с Docker Sandboxes. Другие registry этим путём не поддерживаются. Сетевой доступ по-прежнему зависит от политики песочницы и по умолчанию запрещён.

Чтобы войти через браузер:

```sh
rsbx login
```

CLI покажет код подтверждения и URL. Завершите авторизацию в браузере. Для Docker Hub PAT передавайте токен через стандартный ввод, чтобы он не попал в аргументы процесса:

```sh
read -s DOCKER_PAT
printf '%s\n' "$DOCKER_PAT" | rsbx login --username YOUR_DOCKER_ID --password-stdin
unset DOCKER_PAT
```

`rsbx logout` запрашивает подтверждение и останавливает работающие локальные песочницы перед удалением авторизации Docker account. `rsbx logout --force` пропускает только подтверждение — работающие песочницы всё равно остановятся. Перед подтверждением прочитайте запрос.

## Параметр `--docker`

CLI принимает `--docker` для create/run и включает этим параметром профиль Docker-нагрузки. Профиль привилегированный и может запустить `dockerd`, но вложенные контейнерные операции пока не работают и не прошли security-квалификацию. Наличие параметра в справке не подтверждает, что `docker run` или другие workload-команды выполняются.

```sh
# Экспериментально: команды вложенного Docker сейчас заблокированы.
rsbx run --docker shell .
```

Мы добавим сюда поддерживаемый сценарий после того, как профиль получит отдельную cgroup-изоляцию гостя, минимальный набор capabilities, тесты изоляции, проверки хранилища и жизненного цикла, а также независимое security review. Runtime exec/PTY реализован, но он не включает вложенные контейнеры.

## Отличие от Docker Sandboxes

Docker Sandboxes предоставляет собственный workflow для агентных песочниц и интеграцию с Docker Engine. Rheic — отдельный проект с локальным microVM-runtime. Совместимость с Docker Sandboxes не заявлена. В текущем исходном коде остаются незавершёнными вложенные guest workloads, передача registry credentials и production-квалификация безопасности. Перед использованием функции ознакомьтесь с [моделью безопасности](security.md).
