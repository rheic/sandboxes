# Workspace и файлы

Workspace — это каталог host-системы, подключённый в песочницу. При подключении на запись процессы внутри гостя могут менять файлы host-системы. Добавляйте только необходимые агенту каталоги. Runtime и daemon содержат exec/PTY пути, а ограниченный VM-backed lifecycle прошёл macOS live acceptance; сами параметры CLI не подтверждают безопасность workspace или полную agent parity на каждой платформе.

## Выберите каталоги

Текущий каталог используется как workspace по умолчанию:

```sh
cd /путь/к/проекту
rsbx run shell .
```

Дополнительные каталоги указываются после имени агента. Суффикс `:ro` подключает каталог только для чтения:

```sh
rsbx run shell . /путь/к/справке:ro
```

Флаг `--deny-write` делает подкаталог доступным только для чтения, пока родительский workspace остаётся доступным на запись:

```sh
rsbx run --deny-write ./secrets shell .
```

Если пути workspace не указаны, песочница запускается без подключённых каталогов. Файлы образа гостя при этом доступны.

## Копирование файлов

В команде `rsbx cp` ровно одна сторона должна указывать путь внутри sandbox. Guest-пути должны быть абсолютными:

```sh
rsbx cp ./result.json build:/tmp/result.json
rsbx cp build:/tmp/report.txt ./report.txt
```

Команда копирует обычные файлы и каталоги. Символические ссылки, hard links и специальные файлы по умолчанию запрещены. Флаг `-L` следует по исходной ссылке верхнего уровня; если источник находится внутри workspace, цель ссылки должна оставаться в этом workspace. Вложенные ссылки по-прежнему запрещены.

## Повторный запуск именованной песочницы

`rsbx run --name NAME` повторно использует песочницу и при необходимости запускает её. Явное отличие набора workspace или режима чтения/записи вызывает ошибку, а не скрытую замену подключений. Для другого набора путей задайте новое имя.

## Ограничения

Workspace напрямую открывает гостю доступ к файлам host-системы. Read-only подключение запрещает запись через него, но не скрывает данные из образа гостя и не защищает тот же путь, подключённый на запись отдельно. Очистка после сбоя host и широкая adversarial-проверка файловых операций не завершены. Перед подключением чувствительных данных прочитайте [руководство по безопасности](security.md).
