# Решение проблем

Начните с версии установленного бинарника и его встроенной справки:

```sh
rsbx --help
rsbx diagnose
sandboxesd --help
```

Если daemon-команда не найдена, проверьте наличие бинарника `sandboxesd` в PATH.

`rsbx diagnose` печатает секционный отчёт (installation, platform, storage, connection) из отдельно оценённых проверок со сводкой pass/fail/warning/skip и завершается с ненулевым кодом при падении проверки. `rsbx policy log` показывает записанные в каталоге run daemon решения gateway audit (allowed/denied destinations с сработавшим правилом).

## CLI не подключается

Укажите CLI тот же локальный socket, который использует daemon:

```sh
rsbx --socket "$HOME/.sandboxes/sandboxesd.sock" ls
```

Проверьте, что daemon запущен и текущий пользователь имеет доступ к socket. Переменная `SANDBOXES_SOCKET` задаёт путь по умолчанию. Не заменяйте неизвестный socket или каталог состояния.

## Sandbox не запускается

Команда запуска daemon из [быстрого старта](quickstart.md) работает в state-only режиме: она поднимает control plane, но не настраивает VM backend и потому сама VM не запускает. Для гостевого выполнения нужны совместимые containerd, runtime, guest image, shim и вспомогательные артефакты, настроенные по документации конкретной платформы. Ограниченная live-проверка VM-backed CLI lifecycle прошла на macOS ARM64; это не подтверждает полный агентский workflow. Windows WHPX backend пока не подключён к production daemon, Linux KVM не квалифицированы. Сверьте платформу и режим запуска с [требованиями](requirements.md) и [архитектурой](architecture.md).

## Не работает сеть

Исходящий трафик guest по умолчанию запрещён. Проверьте политику sandbox, настроенный gateway и DNS upstream. Добавляйте только необходимые правила назначения. `rsbx policy check` проверяет сохранённые входные данные политики, но не подтверждает реальное применение фильтра gateway. `rsbx policy log` печатает последние решения gateway audit с сработавшим правилом; `rsbx policy inspect RULE_ID|SANDBOX` показывает детали одного правила или политики sandbox. См. [Сеть и порты](networking.md).

## Вход в Docker прошёл, но guest не скачивает образы

Авторизация аккаунта Docker хранится на хосте. Передача credentials реестра в путь загрузки образов runtime пока не подключена. См. [Docker](docker.md).

## Имя уже связано с другой workspace

Для другой workspace укажите новое имя sandbox или проверьте существующую через `rsbx get NAME`. Не рассчитывайте, что повторное имя переключит подключённый каталог хоста.

## После удаления sandbox файлы хоста остались

Удаление sandbox не удаляет host workspace. Сначала проверьте её расположение, затем удаляйте файлы самостоятельно: Rheic не владеет произвольными каталогами хоста.

Если проблему не удалось решить, проверьте вывод `rsbx diagnose` на локальные пути и чувствительные метаданные и приложите точные версии модулей и платформу. Не прикладывайте credentials или неотредактированные secrets.
